# 评分说明

评分器版本 v2（2026-10-26）。题面没有修改。共 20 条判据：6 条数值正项（R01–R03 各 10 分，D01–D03 各 7 分，合计 51），11 条程序负项和 3 条 LLM 负项（各 −3）。

## 门槛和封顶

三条规则在正负项合成分数之后执行，取其中最低的上限。规则不进分母，也不靠加大扣分来模拟。触发的规则和原因写在 `reward-details.json` 的 `score_rules` 里，`pooling` 另外记下规则前后的分数。通过线是 0.70。

| 规则 | 触发条件 | 总分上限 |
|---|---|---:|
| `required_sheet_gate` | Results 或 Detail 缺失或名字不对 | 0 |
| `required_header_cap` | 必需的前置表头去掉首尾空格后，文字、大小写或顺序不对 | 0.69 |
| `must_clause_cap` | 必需来源为空或只有数字；单位不是 USD；多出不在要求里的业务记录（金额为零也算） | 0.69 |

行序、小数位、重复记录、日期和 Excel 错误值只按对应判据扣分，不封顶。

## 表头和多加的列

题面规定 Results 用 `A1:D1`，Detail 用 `A1:C1`，没有说只能有这几列，所以两张表后面都可以加列，但不能占掉必需字段的位置。表头去掉首尾空格后比较，大小写必须一致。额外的辅助表和空白的样式列都允许。取数总是按规定的位置读，不按实际表头重新定位，以免后面加的同名列把必需列盖掉。

## 小数位和容差

要求两位小数时，下面两种情况任一满足就算合格：数字格式显示两位；或者存储值等于 `round(value, 2)`。题面写“至少 p 位”时，存储值的小数位不少于 p 也算合格。整数金额用常规、一位或三位小数的格式，存储值仍等于两位小数的值，所以合格。存储值多出小数、格式确实显示两位的，也合格。只有存储值超出两位、格式又不显示两位时，才按 S06 扣分。

数值容差另算。R01–R03、D01–D03 都是从整数美元台账和正好 10% 的佣金率算出来的，任何合理的中间舍入顺序都不会差出分币，所以统一用 0.005 USD，不放宽：差 0.0049 和 0.005 接受，差 0.0051 不接受。日期照抄原来的 `Termination date` 字段，不涉及金额容差。

## LLM 判据和程序判据的分工

三条 LLM 判据的文字和权重都没有改，见题包的 `tests/rubrics.toml`。题包的 `tests/prompt.md` 规定裁判只评这三个负项，不重评程序负责的数值、记录、汇总和格式。

| 判据 | 只检查什么 | 和程序判据的边界 | 是否和参考答案的文字比较 |
|---|---|---|---|
| L01 | 候选引用的文件、页码、表格是否真的在随包输入里 | S04 和 `must_clause_cap` 只管来源是否为空或只有数字；多出的记录归 P02、S05。来源写了但是编的，才由 L01 判，没写来源不在这里重复扣分。 | 否。按输入核对，参考答案只作参照。 |
| L02 | 没有证据的外部审计、实时查询或独立核验声明 | 没有对应的程序判据。正常的分析措辞不扣分。 | 否。按候选的说法和随包证据判断。 |
| L03 | 说明文字里输入中没有的新增经营事实 | 算错数归 R01–R03、D01–D03；编造来源归 L01；多出的记录归 P02、S05。都不由 L03 重复扣分。 | 否。按输入逐项核对新增的事实。 |

## 程序负项（各 −3）

| 判据 | 检查内容 |
|---|---|
| V01 | Detail 里 A 方案的原始日期照抄正确 |
| V02 | Detail 里 B 方案的原始日期照抄正确 |
| V03 | Detail 里 C 方案的原始日期照抄正确 |
| S01 | Results 的必需标签按题面顺序列出，文字和题面一致 |
| S02 | Results 三条必需结果的单位是 `USD` |
| S03 | 必需表的前置表头去掉首尾空格后，大小写、文字和顺序一致。不符时扣分并封顶 0.69。后面可以加列。 |
| P01 | 已评分的单元格以外出现 Excel 错误值 |
| P02 | Detail 不能多出没有依据的方案、重复的方案或没有标签的业务记录 |
| S04 | Results 每条必需结果都有来源或支持说明，不为空，也不只是数字。违反时扣分并封顶 0.69。这一条不核查来源是否真实。 |
| S05 | Results 不能多出 Plan D 这类额外方案、重复方案或没有标签的业务记录 |
| S06 | 六个金额显示两位小数，或存储值等于 `round(value, 2)`。不符时扣分，不封顶。 |

## 裁判读取校验

LLM 裁判必须先打开候选工作簿，每条理由都要引用候选里实际存在的工作表和单元格。如果程序能读取工作簿，裁判却说文件不存在、读不到，或者理由里没有引用候选单元格，这次评分记为裁判错误（`verifier_error=1`，`judge:artifact_access_error`）。裁判错误不算答卷分数，也不计入一致性统计。候选引用的来源文件不存在，是答卷的问题，按来源判据扣分，不算裁判错误。

## 复现

运行 `python3 -B validation/run_regression.py`，会检查正负例、分数合成规则、裁判读取校验和已保存的评分记录。它不调用求解模型，也不调用裁判。

LLM 裁判是 claude-sonnet-5-5。参考答案的 5 次评分（`judge_runs/golden_r1` 到 `golden_r5`）都来自它，总分和每条判据的标准差都是 0。旧的 qwen 判定保留在 `history/`，不参与统计。
