# 评分说明

评分器版本是 v2（2026-10-26）。题面没有修改。本题有 20 条判据：

- 6 条程序正项：R01–R03 每条 10 分，D01–D03 每条 7 分，合计 51 分。
- 11 条程序负项，每条 −3。
- 3 条 LLM 负项：L01–L03，每条 −3。

## 术语

- **答卷**：模型交出的 `answer.xlsx`。
- **参考答案**：出题方写的标准答卷。
- **判据**：一条评分规则。程序判据由脚本检查。LLM 判据由裁判检查。
- **裁判**：执行 LLM 判据的模型。

## 整卷 0 分和封顶

评分器先合成正负项分数，再套用以下三条规则，取最低的上限。规则不进分母。触发的规则和原因写在 `reward-details.json` 的 `score_rules` 中。`pooling` 记录规则前后的分数。通过线是 0.70。

| 规则 | 触发条件 | 总分上限 |
|---|---|---:|
| `required_sheet_gate` | Results 或 Detail 缺失或名字不对 | 0 |
| `required_header_cap` | 必需的前置表头去掉首尾空格后，文字、大小写或顺序不对 | 0.69 |
| `must_clause_cap` | 必需来源为空或只有数字；单位不是 USD；多出要求以外的业务记录（金额为 0 也算） | 0.69 |

行序、小数位、重复记录、日期和 Excel 错误值只扣分，不封顶。

## 表头和多加的列

- 题面规定 Results 用 `A1:D1`，Detail 用 `A1:C1`。题面没有规定只能有这几列。
- 两张表都可以在后面加列。加的列不得占用必需字段的位置。
- 评分器比较表头时，先去掉首尾空格。大小写必须一致。
- 答卷可以加辅助表，也可以加空白的样式列。
- 评分器总是按规定的位置读数，不按实际表头重新定位。这样，后面加的同名列不会覆盖必需列。

## 小数位

题面要求两位小数。以下任一条件满足时，小数位合格：

- 数字格式显示两位小数。
- 存储值等于 `round(value, 2)`。

补充规则：

- 题面写“至少 p 位”时，存储值的小数位不少于 p 也合格。
- 整数金额用常规、一位或三位小数的格式时，存储值仍等于两位小数的值。所以这种答卷合格。
- 存储值有多余的小数、格式显示两位时，答卷合格。
- 存储值超过两位、格式又不显示两位时，S06 扣分。

## 数值容差

- R01–R03 和 D01–D03 都来自整数美元台账和正好 10% 的佣金率。
- 任何合理的中间舍入顺序都不会产生分币差异。所以容差统一是 0.005 USD，不放宽。
- 差 0.0049 和 0.005 时接受。差 0.0051 时不接受。
- 日期照抄原来的 `Termination date` 字段。日期不使用金额容差。

## LLM 判据的分工

三条 LLM 判据的文字和权重没有改，见题包的 `tests/rubrics.toml`。题包的 `tests/prompt.md` 规定：裁判只评这三条，不重评数值、记录、汇总和格式。

| 判据 | 检查内容 | 不检查的内容 | 是否和参考答案的文字比较 |
|---|---|---|---|
| L01 | 答卷引用的文件、页码、表格是否在随包输入中存在 | 来源是否为空（S04、`must_clause_cap`）；多出的记录（P02、S05）。答卷没写来源时，L01 不重复扣分。 | 否。按输入检查。参考答案只作参照。 |
| L02 | 没有证据的外部审计、实时查询或独立核验声明 | 没有对应的程序判据。正常的分析措辞不扣分。 | 否。按答卷说法和随包证据检查。 |
| L03 | 说明文字中输入里没有的新增经营事实 | 数值错误（R01–R03、D01–D03）；编造来源（L01）；多出的记录（P02、S05） | 否。按输入逐项检查。 |

## 程序负项（每条 −3）

| 判据 | 检查内容 |
|---|---|
| V01 | Detail 中 A 方案的原始日期照抄正确。 |
| V02 | Detail 中 B 方案的原始日期照抄正确。 |
| V03 | Detail 中 C 方案的原始日期照抄正确。 |
| S01 | Results 的必需标签按题面顺序列出。标签文字和题面一致。 |
| S02 | Results 三条必需结果的单位是 `USD`。 |
| S03 | 必需表的前置表头去掉首尾空格后，大小写、文字和顺序一致。不符时扣分，并封顶 0.69。后面可以加列。 |
| P01 | 已评分的单元格以外，不得有 Excel 错误值。 |
| P02 | Detail 不得多出没有依据的方案、重复的方案或没有标签的业务记录。 |
| S04 | Results 每条必需结果都有来源或支持说明。说明不为空，也不只是数字。违反时扣分，并封顶 0.69。这条判据不检查来源是否真实。 |
| S05 | Results 不得多出 Plan D 这样的额外方案、重复方案或没有标签的业务记录。 |
| S06 | 六个金额显示两位小数，或存储值等于 `round(value, 2)`。不符时扣分，不封顶。 |

## 裁判读取校验

- 裁判必须先打开答卷。
- 裁判的每条理由必须引用答卷中存在的工作表和单元格。
- 程序能打开答卷、裁判却说读不到时，这次评分记为裁判错误。
- 裁判没有引用答卷单元格时，这次评分也记为裁判错误。
- 裁判错误的记录是 `verifier_error=1` 和 `judge:artifact_access_error`。裁判错误不算答卷分数，不进入一致性统计。
- 答卷引用的来源文件不存在时，这是答卷的错误。来源判据扣分，不记为裁判错误。

## 复现

运行 `python3 -B validation/run_regression.py`。这个检查覆盖正负例、分数合成规则、裁判读取校验和已保存的评分记录。它不调用求解模型和裁判。

当前裁判是 claude-sonnet-5-5。参考答案的 5 次评分在 `judge_runs/golden_r1` 到 `golden_r5`。总分和每条判据的标准差都是 0。旧的 qwen 判定在 `history/` 中，不参与统计。
