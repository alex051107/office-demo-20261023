# 电力监管：Powercor 2020 资本支出调节 — 交付说明

## 交付物

答卷是一个 Excel 工作簿（`answer.xlsx`），包含 Results 一张必需表。题包里有输入原件、参考答案（`solution/golden_output/answer.xlsx`，`solution/golden/` 是同一份）、评分器和离线正负例。

## 评分方式

评分器版本是 v2（2026-10-26）。

正项按答对的程度得分，负项按违规的程度扣分，负项不进分母。先算

`总分 = (正项得分之和 − 负项扣分之和) ÷ 30`

结果截到 0 到 1 之间。再套用两条规则，触发时取较低的值。通过线是 0.70。

- Results 缺失或名字不对，整卷 0 分。
- 违反题面里“必须”的条款，总分最高 0.69。这类条款有四种：必需的前置表头不对；必需的来源为空或只有数字；单位不对；必需表里多出编造的业务记录。题面只规定了前几列，所以后面多加列、空白的样式列和自己组织的辅助表都允许。

行序、重复记录、数值和小数位这些问题不封顶，按对应判据逐项扣分。

每条判据的权重、舍入规则，以及程序判据和 LLM 判据怎么分工，见 [评分说明](validation/scoring_policy.md)。

| 答卷 | 当前分数 | 裁判情况 |
|---|---:|---|
| 参考答案 | 1.000000 | Sonnet 评 5 次，5 次有效，通过 |

参考答案的分数取 Sonnet 第 1 次评分。旧的暂定分、被替换的记录和无效的裁判尝试都在 `history/`，不参与统计。每个模型只跑了一次，没有 pass@8。

## 离线复现

需要 Python 3.11 以上和 openpyxl，不需要裁判凭据。把题包和轨迹报告两个文件夹放在一起，然后在本目录运行：

```sh
python3 -B validation/run_regression.py
python3 -B validation/validate_paths.py
```

回归检查覆盖 24 个负例和 13 个正例，也会核对分数合成规则、裁判读取校验和已保存的评分记录。它只在本地检查，不调用求解模型或裁判，也不改动交付文件。轨迹报告不在旁边时，用 `run_regression.py --trajectory <轨迹报告目录>` 指定位置。

修改经过见 [历史变更记录](history/CHANGELOG.md)，`history/` 的分组见 [历史目录说明](history/README.md)。

## 裁判更换（2026-10-26）

LLM 裁判从 qwen3.7-plus 换成了 claude-sonnet-5-5。qwen 常常没打开答卷就给出判定。这次三道题一共做了 16 次 Sonnet 评分，每次都打开了工作簿，并在理由里引用了候选单元格。判据、权重、程序规则和所有答卷都没有改。

参考答案用 Sonnet 评了 5 次，5 次都有效，总分都是 1.0。总分和每条判据的标准差都是 0，低于 0.05 的要求。上一版只有 2 次有效。`judge_runs/golden_r1` 到 `golden_r5` 是这 5 次的记录，`golden/` 用的是第 1 次。

三个模型的答卷没有重评。它们的程序分都是 0，三条 LLM 判据只会扣分，总分最低截到 0，所以换哪个裁判都是 0 分。这些答卷保留原来的评分记录。

运行评分时请显式设置 `JUDGE_MODEL`。`task.toml` 的默认值是 claude-sonnet-5-5；如果直接运行 `tests/test.sh` 又没设这个变量，平台模板会退回 qwen3.7-plus。

旧的 qwen 评分记录在 `history/judge_sonnet_20261026/previous/`。
