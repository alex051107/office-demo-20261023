# 评分说明

评分器版本 v2（2026-10-26）。共 13 条判据：3 条数值正项（R01–R03，各 10 分，合计 30），7 条程序负项和 3 条 LLM 负项（各 −3）。

## 表头和多加的列

题面只规定了 Results 的 `A1:D1` 四个表头，没有说整张表只能有四列。所以后面多加列、空白的样式列、自己组织的辅助表都允许。表头去掉首尾空格后比较，大小写和顺序必须一致。评分器不会按表头去别的表里找答案：Results 缺失或改了名，整卷 0 分。

## 门槛和封顶

两条规则在正负项合成分数之后执行，不进分母，也不靠加大扣分来模拟。触发的规则和原因写在 `reward-details.json` 的 `score_policy` 里。

| 规则 | 触发条件 | 总分上限 |
|---|---|---:|
| `required_sheet_gate` | Results 缺失或名字不对 | 0 |
| `must_clause_cap` | 表头不对；任一必需结果的来源为空或只有数字；单位不对；Results 里多出带业务值、但标签不在必需列表里的记录 | 0.69 |

行序、重复的必需行和小数位只按判据扣分，不封顶。只有文字、没有业务值的备注行不算多出的记录。辅助表不受 Results 结构的限制。

数值按题面固定的 A、B 两列读取。只把表头换了位置、数据没动的答卷，数值仍能得分，再封顶到 0.69，不会因为表头不对就被当成结果全错。

## 小数位和容差

题面要求三位小数（p=3）。下面两种情况任一满足就算合格：单元格格式显示三位；或者存储值本身等于四舍五入到三位的值。题面写“至少 p 位”时，存储值的小数位不少于 p 也算合格。所以存了完整精度、格式只显示两位的答卷也合格，存成 1.2、1.23 这样的短小数也合格。这条规则只管小数位，不放宽数值准确性。

直接摘录的数值，容差是 0.0005 AUD million。三个结果都是汇总值：先把每类资产的差额舍入到三位再相加，是等价的算法，会累积舍入误差。网络和非网络各有三项非零差额，误差最多 3×0.0005=0.0015；全部资产有七项非零差额（另外五项正好为零），最多 7×0.0005=0.0035。所以 R01、R02 的容差是 0.0015，R03 是 0.0035，都没有相对容差。我们建议保留完整精度，到输出时再舍入。

按“先舍入再汇总”算出来是网络 13.691、非网络 −11.545、合计 1.145。回归正例 `rounded_asset_aggregation.xlsx` 专门覆盖这种算法。计算方法是实际净资本支出乘年末因子，再减去预测净资本支出；合计包括 Land。

## LLM 判据和程序判据的分工

三条 LLM 判据的文字和权重（−3）都没有改。模型答卷沿用当时保存的 LLM 判定。

| 判据 | 只检查什么 | 是否和参考答案的文字比较 |
|---|---|---|
| L01 | 候选引用的文件、页码、表格是否真的在输入里。来源是否为空归 S03，多出的记录归 S05，数值归 R01–R03，不重复扣分。 | 否。对照随包输入，参考答案只是被评的对象。 |
| L02 | 候选是否声称做过外部审计、实时查询或独立核验，而输入和候选里都没有证据。没有对应的程序判据。 | 否。对照输入和候选证据。 |
| L03 | 候选是否编造了输入里没有的公司经营事实。数值错误、来源定位和多出的记录分别归 R01–R03、L01、S05。 | 否。按输入核对，不比较和参考答案文字是否相似。 |

## 程序负项（各 −3）

| 判据 | 检查内容 |
|---|---|
| S01 | Results 前四列表头去掉首尾空格后是 `label`、`value`、`unit`、`source_note`，大小写和顺序一致，后面可以加列。不符时扣分并封顶 0.69。 |
| S02 | 每条必需结果的单位是 `AUD million nominal`。不符时扣分并封顶 0.69。 |
| S03 | 每条必需结果的来源不为空，也不只是数字。不符时扣分并封顶 0.69。 |
| S04 | 三条必需结果从第 2 行起按题面顺序排列，不缺、不重复、不颠倒。 |
| S05 | Results 不能多出带业务值、但标签不在必需列表里的记录，违反时扣分并封顶 0.69。重复的必需标签也扣分，但不单独封顶。 |
| S06 | 三位小数：格式显示三位，或存储值等于舍入到三位的值。数值误差另按各行容差判断。 |
| P01 | 已评分的结果单元格以外出现 Excel 错误值。 |

## 裁判读取校验

LLM 裁判必须先打开候选工作簿，每条理由都要引用候选里实际存在的工作表和单元格。如果程序能读取工作簿，裁判却说文件不存在、读不到，或者理由里没有引用候选单元格，这次评分记为裁判错误（`verifier_error=1`，`judge:artifact_access_error`）。裁判错误不算答卷分数，也不计入一致性统计。候选引用的来源文件不存在，是答卷的问题，按来源判据扣分，不算裁判错误。

## 复现

运行 `python3 -B validation/run_regression.py`，会检查正负例、分数合成规则、裁判读取校验和已保存的评分记录。它不调用求解模型，也不调用裁判。

LLM 裁判是 claude-sonnet-5-5。参考答案的 5 次评分（`judge_runs/golden_r1` 到 `golden_r5`）都来自它，总分和每条判据的标准差都是 0。旧的 qwen 判定保留在 `history/`，不参与统计。
