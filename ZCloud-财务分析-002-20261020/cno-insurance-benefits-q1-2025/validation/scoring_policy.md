# 评分说明

评分器版本是 v2（2026-10-26）。本题有 23 条判据：

- 4 条程序正项：R01、R02 每条 10 分，A1、A2 每条 7 分，合计 34 分。
- 16 条程序负项，每条 −3。
- 3 条 LLM 负项：L01–L03，每条 −3。

## 术语

- **答卷**：模型交出的 `answer.xlsx`。
- **参考答案**：出题方写的标准答卷。
- **判据**：一条评分规则。程序判据由脚本检查。LLM 判据由裁判检查。
- **裁判**：执行 LLM 判据的模型。

## 整卷 0 分和封顶

评分器先合成正负项分数，再套用以下三条规则。规则不进分母。触发的规则和原因写在 `reward-details.json` 中。

| 规则 | 触发条件 | 总分上限 |
|---|---|---:|
| `required_sheet_gate` | Results、Analysis 或 Summary 缺失或名字不对 | 0 |
| `required_header_cap` | 必需表头去掉首尾空格后，文字、大小写或顺序不对 | 0.69 |
| `instruction_must_clause_cap` | 来源字段为空或只有数字；单位不对；多出带业务值、标签不在要求中的记录 | 0.69 |

- 评分器不按表头到别的表里找答案。
- 题面只规定每张表的前几列。答卷可以在后面加列，可以加空白的样式列，也可以加辅助表。
- 行序、重复记录、小数位和来源定位只扣分，不封顶。

## 小数位和容差

- 金额要求一位小数。百分比要求两位小数。
- 以下任一条件满足时，小数位合格：格式显示要求的位数；存储值等于舍入到这个位数的值。
- 百分比格式按百分点比较。
- 本题没有“至少 p 位”的要求。
- 金额的容差是 0.05 百万美元。百分比的容差是 0.005 个百分点。
- 输入和累计调整都是一位小数。季度加减不产生额外的舍入误差。所以容差没有放宽。

## LLM 判据的分工

程序判据检查以下内容：

- 来源字段中的文件、表格和单元格是否存在（SD1、SD2、S02、SP1）。
- 来源是否为空（S01）。
- 数值、记录、顺序、单位和格式。

LLM 判据只检查程序判据检查不了的内容：

- L01：来源字段以外，答卷新写的来源说法是否编造。
- L02：答卷是否声称做过外部审计、实时查询或独立核验，但没有证据。
- L03：答卷是否编造输入中没有的公司经营事实。

三条 LLM 判据的文字和权重没有改。LLM 判据不和参考答案的文字比较。模型答卷沿用当时保存的 LLM 判定。

## 程序负项（每条 −3）

| 判据 | 检查内容 |
|---|---|
| P1 | Summary 中第四季度的赔付额等于 Analysis 中的记录。 |
| P2 | Summary 中第一季度减第四季度，等于 Results 中的变化额。 |
| SD1 | Analysis 第四季度一行的来源是随包提供的文件。 |
| SD2 | Analysis 第一季度一行的来源是随包提供的文件。 |
| F1 | Results 有题面规定的 4 个表头。 |
| F2 | Analysis 有题面规定的 6 个表头。 |
| F3 | Summary 有题面规定的 2 个表头。 |
| X1 | 工作簿的任何单元格都不得有 Excel 错误值。 |
| X2 | 必需表不得有多出的业务记录、键为空但有内容的记录或重复记录。 |
| S01 | Results 的 `source_note`、Analysis 的 `source_document` 和 `source_page` 不为空，也不只是数字。 |
| S02 | Results 的来源指向随包文件中存在的工作表或表格。来源写了单元格时，单元格必须在这张表的范围内。来源可以明确引用第 2 行的来源。 |
| SP1 | Analysis 每一行的 `source_page` 是随包文件中存在的工作表或表格。 |
| O01 | Results、Analysis、Summary 的必需记录按题面顺序各出现一次。不得缺少、颠倒或重复。 |
| U01 | Results 两行的单位分别是 `USD millions` 和 `percent`。Analysis 两行的单位都是 `USD millions`。 |
| DP1 | Results 的金额变化显示一位小数，或存储值等于舍入到一位的值。 |
| DP2 | Results 的百分比显示两位小数，或存储值等于舍入到两位的值。 |

F1–F3 比较表头时，先去掉首尾空格。大小写和顺序必须一致。后面可以加列。

## 裁判读取校验

- 裁判必须先打开答卷。
- 裁判的每条理由必须引用答卷中存在的工作表和单元格。
- 程序能打开答卷、裁判却说读不到时，这次评分记为裁判错误。
- 裁判没有引用答卷单元格时，这次评分也记为裁判错误。
- 裁判错误的记录是 `verifier_error=1` 和 `judge:artifact_access_error`。裁判错误不算答卷分数，不进入一致性统计。
- 答卷引用的来源文件不存在时，这是答卷的错误。来源判据扣分，不记为裁判错误。

## 复现

运行 `python3 -B validation/run_regression.py`。这个检查覆盖正负例、分数合成规则、裁判读取校验和已保存的评分记录。它不调用求解模型和裁判。

当前裁判是 claude-sonnet-5-5。参考答案的 5 次评分在 `judge_runs/golden_r1` 到 `golden_r5`。总分和每条判据的标准差都是 0。旧的 qwen 判定在 `history/` 中，不参与统计。
